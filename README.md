# Mlogent-Ops

蓝图预览同步每名玩家最多 500 个建筑，超过部分不向其他玩家展示；不修改玩家本地蓝图或实际建造队列。此限制在原生同步前执行，同时裁剪预览接收缓存和已提交缓存。`previewPlansTrimmed` 记录裁剪条目次数（含重复预览），`previewPlanError` 记录限制器异常。

受控单位 100ms 补发排除 `BlockUnitc` 建筑控制代理。其建筑引用不参与实体序列化，作为普通实体发送可能导致客户端小地图空指针崩溃；正常移动单位仍保留补发。

Mlogent 的独立服务器维护项目。管理同步策略、性能实验、部署资源预算和故障留档。

## 职责边界

- 本项目：C 组视野分频、错峰、远处单位轮转、资源保护、流量/进程遥测、回退留档、systemd 配置和实验报告。
- Mlogent 主体：MCP/OAuth/知识库/编译与仿真，以及游戏世界的业务 API、运行器和休眠协议。
- 主体只保留可选扩展加载接口；未安装本项目时使用原版同步路径。运维模块不复制主体实现。

## 使用

需要 Python 3.10+；策略回归测试需要 Node.js。常规运行无第三方 Python 依赖。

```powershell
python -m pip install -e D:\Develop\Mlogent-Ops
$env:MLOGENT_ROOT = 'D:\Develop\MlogAgent'
python -m mlogent_ops.world_traffic --help
python tools/check.py
```

Mlogent 服务设置 `MLOGENT_OPS_ROOT=/opt/mlogent-ops` 后即可加载本项目。
运维服务设置 `MLOGENT_ROOT` 指向实际 Mlogent 发布目录，通过现有本机控制口取数，不发起唤醒。

## 当前实验配置

### 资源自适应与单路实体同步

受控单位由独立补发路径发送，不再同时进入普通实体快照。补发失败时普通路径接管；
PvP 或原版同步回退不叠加该补发。每次只发送一轮，卡顿后跳过错过的时隙，不追发积压。

启用 `adaptiveBandwidth` 时，带宽采集服务同时读取世界服务 cgroup 的实际 CPU 配额和
使用量、主机 CPU 与可用内存，并结合游戏帧间隔和堆占用限制最高同步频率。
资源状态初始为普通档；连续 30 秒有余量才逐档加速，持续压力则逐档放慢。

| 资源档位 | 近景普通单位间隔（叠加带宽档位） | 受控单位间隔 |
| --- | --- | --- |
| 有余量 | 100 / 150 / 200 / 300ms | 100ms |
| 普通 | 200 / 250 / 300 / 400ms | 100ms |
| 承压 | 250 / 300 / 400 / 500ms | 150ms |
| 更高压力 | 300 / 350 / 450 / 500ms | 200ms |

余量要求包括：世界 CPU 使用低于配额的 65%、主机 CPU 低于 75%、可用内存至少
192MiB、堆占用低于 75%、帧间隔 p95 不超过 22ms 且无 80ms 长帧。
持续 CPU 超过配额的 85%、可用内存低于 144MiB 或长帧等会限制频率；
原有紧急内存、主线程保护和原版回退保持有效。资源反馈过期超过 10 秒时失去加速，
回到普通档；带宽反馈过期则恢复原有 C 节奏。全图、大视野采用更保守的间隔。
以下各项中的 200ms/100ms 是普通资源档基准；AFK 玩家仍优先使用原有 1000ms 规则。

- `rotatingNotices: true` 开启 AFK → polyAI → MCP 帮助轮播，默认每 5 分钟只发送一条。仅有已连接玩家且游戏运行时发送，空服等待下一周期，不补发错过的公告。未启用的验证规则自动跳过；MCP 公告引导使用 `/mcp` 私下查看配置，不广播凭据。监听器在热重载时复用，避免重复广播。

- `polyVerification: true` 启用合作建造请求启发式验证（独立于同步优化回退与 PvP）。60 秒内同一玩家在至少 5 个不同的同队建筑计划上晚于另一名仍连接玩家发起放置请求，显示原版三选一问题；同一目标的重复快照只计一次，首发玩家不计跟随。30 秒超时、答错或关闭即以 0ms 封禁期踢出；答对给予 5 分钟免重复验证。记录原计划带配置、后续计划缺配置的迹象，不声称证明 polyAI 或配置破坏；不缓存池化 PlayerAction 对象。最多保留 2048 个目标槽，每秒清理 32 个；离服清状态，换图清全部。菜单发送失败不处罚，监听异常关闭该检测。与 AFK 验证分别使用独立菜单，polyAI 待验证期间暂缓 AFK，polyAI 答对同时满足 AFK。该验证可以被自动解题或请求伪装绕过，正常合作也可能触发，需要玩家作答。

- `afkVerification: true` 沿用旧配置键，现在启用自动 AFK，不再验证或弹菜单。仅在实验 C 组、非 PvP 且 C 优化仍启用时生效。连续 180 秒没有聊天或建造／建筑配置／单位控制交互后，自动进入 AFK，名字前添加 `[yellow][AFK][]`，该接收者单位同步降到 1000ms，不踢人。任意非空聊天消息（含命令），或尝试建造、拆除、旋转、配置建筑、接管建筑或控制／指挥单位，立即解除 AFK 并清除标识；交互尝试仍须通过原有权限检查。解除时刷新接收者建筑缓存与发送调度，不绕过独立带宽和资源限制。移动、心跳、镜头和自动挖矿不重置计时。离服、换图、停用策略清理状态和标识，旧 `/afkverify` 命令移除。名字标识接入 Wayzer 前缀管线，不恢复游客或昵称后缀。

- `adaptiveBandwidth: true` 在实验 C 组开启每玩家 200kbps 下行目标反馈调频，需运行 `deploy/mlogent-world-bandwidth.service`。服务每 2 秒计量公网 6567 端口 IPv4 下行（含 IP/TCP/UDP 头），只在内存保留地址汇总，通过现有本地控制接口反馈，休眠时不唤醒世界。每玩家使用平滑平均值；同公网地址玩家均分地址总量（近似值，可能含同地址列表查询）。持续超过 220kbps 降档，低于 170kbps 后缓慢恢复；首次反馈后保留 20 秒适应期，降档至少相隔 10 秒，升档至少相隔 20 秒。近景单位 200/250/300/400ms，全图 300/350/400/500ms，远景六桶随单位周期变为约 1.2–2.4 秒。100ms 受控单位、冲反、心跳和原版事件保留；无法保证硬带宽上限，不丢关键消息。反馈超过 10 秒未更新恢复原 C 节奏。PvP 不使用自适应降频；同队建筑周期不变。服务最多记 256 个公网地址、单个待反馈窗口，CPU 10%、内存 48MiB 保护；采集丢包和分片可能使实测低估。

- 实验 C 组设置 `enemyBuildingsInViewOnly: true` 后，不同队伍的建筑在接收玩家兴趣区之外不发送周期建筑快照（包括敌方冲反优先通道）；战争迷雾仍优先过滤，重新进入兴趣区强制刷新。同队建筑保留远处低频和冲反优先更新。兴趣区沿用镜头尺寸的 1.5 倍及建筑半径边缘余量；镜头数据无效时按完整范围发送。换队清空该接收者建筑调度状态。此规则不改变单位、建造/拆除事件和其他原版 RPC，也不在 PvP 或建筑数量超出自定义容量而回退原版时承诺过滤。

- `snapshot-profile.json` 中设置 `buildingObservation: true` 可启用建筑同步字节重复率抽样。只比较已经序列化并交给原版网络发送的记录，不改变发包频率、不跳过更新。全服每秒最多抽样 8 条，每条最多 2KiB，缓存最多 64 条（字节数组合计最多 128KiB）；换图清空缓存，采样异常只关闭观测。记录样本、可比较样本、完全重复样本、字节数及比较耗时；这些是抽样指标，不能直接当作全服可节省带宽。空服休眠期间没有新样本。
- 实验 C 组设置 `buildingDedup: true` 启用有限建筑去重，同时启用上述有界比较器。仅跳过同一接收者、队伍、建筑身份且完整字节一致的记录；24 秒后在下一次原有建筑调度强制发送，进入视野、迷雾揭开、替换建筑和冲反优先通道不跳过。未比较的记录正常发送并使旧比较基线失效。保留原版包格式，过滤后重写记录数；整包为空时不发送。比较异常恢复完整数据包，发送异常清空缓存并交给原有回退机制。`skippedRecords/Bytes/Packets` 是实际跳过量，`sentPayloadBytes` 不包含网络协议头，不能视作公网总流量；建筑原计数仍表示已序列化候选数。这阶段不改变单位节奏，也不提前检查尚未到期的建筑变化。

- 大视野旁路按玩家独立判断：小视野继续 200ms 近景与六批远景同步，大视野或无效镜头仅对该玩家使用 300ms 全量单位快照；状态、建筑、受控单位补发不受其他玩家镜头影响。
- C＋错峰＋远处单位六批轮转：视野内单位 200ms；状态/建筑调度 300ms；远处普通单位约 1.2 秒覆盖一轮；所有受控单位全图补发 100ms，仍遵守战争迷雾。
- 冲击反应堆热量低于 0.7 时走独立 500ms 优先通道，达到 0.7 时补发一次最终状态，再恢复普通建筑周期。仍遵守迷雾与软预算；过载时记录实际间隔，不保证绝对时限。
- 连续三次调度超过 100ms，或更新间隔超过 5 秒才因时间回退；建筑软切片保持 2ms。
- 主机可用内存低于 96MiB 持续 10 秒，或低于 64MiB 立即回退；堆使用超过 93%，或 JVM 交换超过 128MiB 也回退。
- 入服与优化策略保护上限统一为 12 人；这不是已经完成的 12 人负载压测结论。
- 平时仅内存滚动记录；保护回退时保存前 90 秒、后 30 秒，最多 20 份。正常数据不持续落盘。

部署与迁移方式见 `docs/deployment.md`。历史实验依据见 `reports/`；`experiments/legacy/` 是当时的一次性脚本，保留原始路径作参考，不是生产入口。

## 语言支持与发布包

`deploy/mlogent-push-relay.service` 将游戏 `/push` 的持久化请求交给服务器 Agent
收件箱，不自动发送到 QQ 群。需同时启用主体的原生 push 处理器与 AstrBot Agent
插件；回复通过请求 ID 绑定原玩家连接。写入收件箱失败时保留请求重试。
仅运行服务不会自动创建 Agent 或模型配置。

Mlogent 的 AFK、polyAI 和轮播提示支持简体中文与英文，默认跟随客户端语言；
使用 `/language zh`、`/language en` 或 `/language auto` 设置。
Wayzer 独立使用 `/lang zh` 或 `/lang en`，部分硬编码菜单仍保留原文。
游戏内 `/mcp` 弹出网站链接确认，确认后前往 `https://mcp.iliary.life/`。

Release 提供独立的 `mlogent-ops-<version>.zip` 和 `SHA256SUMS.txt`。
包内包含 `mlogent_ops/`、部署模板、文档、回归测试与历史实验报告；
不包含 Mlogent 主体、Java 运行时、在线存档或服务器凭据。
从仓库运行 `python tools/build_release.py` 可重新构建，运行
`python tools/check.py` 验证策略。历史报告中的旧设置以报告日期为准。

不得把 SSH 私钥、MCP/OAuth token、密码、聊天记录或连续采样原始文件提交到本仓库。
